# Agent Implementation Plan (Plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `agent`, a cross-platform (Linux, macOS, Windows) user-space RFC 9686 client that registers every eligible self-generated IPv6 address with the collector and with any RFC 9686 server on the link, and runs as a system service.

**Architecture:** OS-specific code is confined to two seams: `internal/agent/addrsrc` (list addresses with their origin and DAD state, plus a change-notification channel) and `internal/agent/duid` (read the OS's DUID). The rest is portable and tested with fakes:
- `internal/agent/sched`: a pure, clock-driven per-address state machine for retransmit, refresh and heartbeat.
- `internal/agent/sender`: message building, per-address UDP sockets, reply matching and the option-148 multicast probe.
- `internal/agent`: the runner that ties them together.

`cmd/agent` wraps the runner in `kardianos/service`.

**Tech Stack:** Go 1.26 (`go.mod` says `go 1.26.0`), `golang.org/x/sys/{unix,windows,windows/registry}`, `github.com/kardianos/service`, `howett.net/plist` (darwin only), `github.com/BurntSushi/toml`, the existing `internal/dhcp6`.

**Spec:** `docs/superpowers/specs/2026-11-08-ipv6-ra-logger-design.md` (§4 Agent, §6, §7, §10). Plan 1 (`docs/superpowers/plans/2026-11-08-collector-core.md`) is implemented. This plan builds on its packages.

**Independent of Plan 3 (sniffer).** The only shared file is `test/e2e/e2e_linux_test.go` plus the `radvd` install step in `ci.yml`. Whichever plan lands second reuses the `startRadvd` helper and the install step instead of adding them again.

## Global Constraints

- Module path `github.com/buraglio/ipv6-ra-logger`. Every package builds with `CGO_ENABLED=0` and uses only pure-Go dependencies.
- `cmd/agent` and all `internal/agent/...` packages build and pass `go test -race` on linux, darwin and windows. OS files use `_linux.go`, `_darwin.go`, `_windows.go` suffixes. A `_other.go` file (`//go:build !linux && !darwin && !windows`) returns `errors.ErrUnsupported`, so `go vet ./...` passes everywhere.
- Vendor Class (16) enterprise number defaults to **32473** and is configurable. The data strings are exactly, in this order: `ra-logger-agent/<version>`, `os=<goos>`, `if=<ifname>`, `mac=<current interface MAC>`. The collector depends on the `ra-logger-agent/` prefix (`registrar.AgentPrefix`).
- Each ADDR-REG-INFORM carries a Client ID, exactly one IA Address, Vendor Class and (when encodable) FQDN. It **never** carries a Server ID or an Option Request. The UDP source address is the address being registered.
- Multicast destination `ff02::1:2` port 547 on the address's interface. Unicast to every configured collector, always.
- Timers: initial retransmit timeout 1 s, doubling, at most 3 tries, same XID, lifetimes recomputed on each try. Refresh at `min(0.8 × valid × rand[0.9, 1.1], heartbeat)` with a new XID. Static or infinite-lifetime addresses refresh at `min(4h, heartbeat)`. **Heartbeat defaults to 1h.** A full rescan runs every 5 minutes.
- **No de-registration** in v1, not even on shutdown.
- The client port is 546 with address/port reuse. If binding fails, fall back to an ephemeral port.
- Binary under 10 MB and memory under 20 MB (checked in Task 9).
- GitHub Actions pinned as in `ci.yml` (`actions/checkout@3d3c42e…# v7.0.1`, `actions/setup-go@b7ad1da…# v7.0.0`).

## Spec interpretation notes (decided while planning)

- **Linux DUID sources (spec §10 item 2).** Settled: read only dhclient's `default-duid` (`/var/lib/dhcp/dhclient6.leases`, then `/var/lib/dhclient/dhclient6.leases`). systemd-networkd's machine-id-derived DUID and NetworkManager's internal client are deferred. Hosts using them get a generated DUID-LLT, which stays stable via the state file.
- **DUID order.** config → OS DUID → saved state → generate DUID-LLT. The chosen DUID is always saved, so a host whose OS DUID later disappears keeps the same DUID from state.
- **Linux origin when `IFA_PROTO` is absent or `0`.** This is not limited to old kernels, because NetworkManager adds SLAAC addresses itself without setting a proto. The rule: `IFA_F_PERMANENT` means `static`. Otherwise `/128` with a finite valid lifetime means `dhcpv6`, and other finite lifetimes mean `slaac`.
- **Windows temporary vs stable-privacy.** Both report `IpSuffixOriginRandom` and are classified `slaac`. Both are registered, so the distinction doesn't change behaviour.
- **macOS lifetimes** (verified on macOS 26 with `SIOCGIFALIFETIME_IN6`): `ia6t_expire` and `ia6t_preferred` are wall-clock Unix seconds, and `0` means infinite. Remaining = `max(0, expire − now)`.
- **Per-destination retransmit.** A unicast destination is satisfied by an ADDR-REG-REPLY from that collector's address. The multicast destination is satisfied by any matching reply. The reply means only "stop retransmitting".
- **1% lifetime change.** Lifetimes are recorded as absolute expiry times. If a rescan moves the valid or preferred expiry by more than 1% of the new lifetime (in either direction), the address is due now with a new XID. Infinite↔finite always counts as a change. Normal SLAAC refreshes move expiry by far less than 1%, so they don't trigger.
- **Refresh floor of 10 s,** so an address with a tiny remaining lifetime can't spin.
- **Multicast probe.** In `multicast = "auto"`, each interface is probed (Information-Request with ORO 148 from the link-local address) when its first eligible address appears, and again every heartbeat. It is enabled iff a Reply carries option 148. `"always"` skips the probe.
- **FQDN.** `hostname` from config, else `os.Hostname()`. If `dhcp6.EncodeFQDN` rejects it, the option is omitted and a debug line is logged once.
- **Linux service** uses `DynamicUser=yes` + `StateDirectory=ra-logger-agent` instead of a sysusers entry. The agent needs only UDP sockets and netlink, plus read access to dhclient leases, which `ProtectSystem=strict` allows.
- **Kea interop** uses the stable Kea 3.0 packages (3.0 includes the RFC 9686 server side from 2.7.7). Kea 3.0 has no `allow-address-registration` key (added in 3.1.4), so the test config omits it.

## Review Focus

1. **The OS removes an address mid-cycle** (SLAAC prefix withdrawn, temporary address expires). The send fails with `EADDRNOTAVAIL` (`WSAEADDRNOTAVAIL` 10049 on Windows), and the address's state is dropped without a crash, retry storm or de-registration. Test: `TestRunnerDropsAddressOnAddrNotAvail` (Task 8).
2. **A corrupt or truncated state file**: it is backed up, a DUID is regenerated, and an Error line with `event=duid.regenerated` is logged. The agent never crashes and never silently changes DUID. Tests: `TestResolveCorruptStateBacksUp`, `TestResolveKeepsSavedDUIDWhenOSDUIDGone` (Task 5).
3. **No collector reachable and no RFC 9686 server on the link**: retransmits stay bounded at 3 per cycle, there is no busy loop, and the agent retries at the next refresh. Test: `TestSchedGivesUpAfterMaxTriesUntilRefresh` (Task 6).
4. **Port 546 already held by the OS DHCPv6 client** (`configd`, Windows DHCP service, dhclient): the agent falls back to an ephemeral port and still registers. Test: `TestTransportFallsBackWhenPortBusy` (Task 7).
5. **Change-notification storms** (interface flapping, a burst of netlink messages): rescans are coalesced to at most one in flight, and the scheduler is not reset (no XID churn). Test: `TestRunnerCoalescesWatchBursts` (Task 8).

`Eligible` is true iff all of these hold:
- `State == StateReady`
- Origin is `slaac`, `temporary` or `static`
- the address is global unicast, including ULA `fc00::/7`
- it is not link-local, not loopback, not multicast, not unspecified, and not an IPv4-mapped (`Is4In6`) address

Classifier constants. Define them locally in `classify.go` so the file builds everywhere:
- **Linux** (`<linux/if_addr.h>`):
  - flags: `IFA_F_TEMPORARY=0x01`, `IFA_F_OPTIMISTIC=0x04`, `IFA_F_DADFAILED=0x08`, `IFA_F_TENTATIVE=0x40`, `IFA_F_PERMANENT=0x80`
  - protos: `IFAPROT_UNSPEC=0`, `IFAPROT_KERNEL_LO=1`, `IFAPROT_KERNEL_RA=2`, `IFAPROT_KERNEL_LL=3`
- **macOS** (`<netinet6/in6_var.h>`, verified against the SDK): `TENTATIVE=0x2`, `DUPLICATED=0x4`, `DETACHED=0x8`, `AUTOCONF=0x40`, `TEMPORARY=0x80`, `DYNAMIC=0x100`, `OPTIMISTIC=0x200`
- **Windows**: use `x/sys/windows` names in comments, with these values:
  - prefix origins: Manual 1, Dhcp 3, RouterAdvertisement 4
  - suffix origins: Manual 1, Dhcp 3, LinkLayerAddress 4, Random 5
  - DAD states: Tentative 1, Duplicate 2, Deprecated 3, Preferred 4

Classification rules:
- **Linux.** First the state: `DADFAILED` → Duplicate; `TENTATIVE|OPTIMISTIC` → NotReady; otherwise Ready. Then the origin, with the first match winning:
  1. `TEMPORARY` → temporary
  2. proto `KERNEL_RA` → slaac
  3. proto `KERNEL_LO` or `KERNEL_LL` → other
  4. `PERMANENT` → static
  5. `prefixLen == 128` with a finite valid lifetime → dhcpv6
  6. otherwise → slaac
- **macOS.** State: `DUPLICATED` → Duplicate; `TENTATIVE|OPTIMISTIC|DETACHED` → NotReady; otherwise Ready. Origin, first match wins: `DYNAMIC` → dhcpv6; `TEMPORARY` → temporary; `AUTOCONF` → slaac; otherwise static.
- **Windows.** State: Preferred or Deprecated → Ready; Duplicate → Duplicate; otherwise NotReady. Origin, first match wins:
  1. suffix Dhcp → dhcpv6
  2. prefix RouterAdvertisement with suffix LinkLayerAddress or Random → slaac
  3. prefix Manual or suffix Manual → static
  4. otherwise → other

### Task 4: Address source OS backends (Linux netlink, macOS ioctl + PF_ROUTE, Windows IP Helper)

**Files:**
- Modify: `internal/agent/addrsrc/addrsrc_linux.go`, `addrsrc_darwin.go`, `addrsrc_windows.go`
- Create: `internal/agent/addrsrc/netlink_linux.go` (byte parser), `netlink_linux_test.go`, `live_test.go`

**Interfaces:**
- Consumes: Task 3 types and classifiers.
- Produces: `New() Source` on each OS, plus on Linux `func parseAddrMsgs(b []byte, now time.Time, names func(int) string) ([]Addr, error)`, a pure parser of `RTM_NEWADDR` messages (testable with canned bytes).

Implementation decisions per OS:
- **Linux.**
  - List: `unix.NetlinkRIB(unix.RTM_GETADDR, unix.AF_INET6)` → `parseAddrMsgs`. Use `unix.ParseNetlinkMessage` and `unix.ParseNetlinkRouteAttr`, and read `unix.IfAddrmsg` from the message body.
  - Attributes: `IFA_ADDRESS`/`IFA_LOCAL` (prefer `IFA_LOCAL` when present), `IFA_FLAGS` (8, a u32 that overrides the 8-bit `ifa_flags`), `IFA_CACHEINFO` (6: `ifa_prefered`, `ifa_valid`, u32 each), `IFA_PROTO` (11, u8; may be absent).
  - Interface names come from `net.InterfaceByIndex`.
  - Watch: an `AF_NETLINK`/`NETLINK_ROUTE` socket bound to group `RTMGRP_IPV6_IFADDR` (`0x100`). A goroutine reads it and sends a non-blocking signal per datagram. It closes the socket on ctx done; set `SO_RCVTIMEO` to 1 s so the loop observes ctx.
- **macOS.**
  - List: `net.Interfaces()` + `ifi.Addrs()` for the IPv6 addresses. Then two ioctls per address on an `AF_INET6` `SOCK_DGRAM` socket via `unix.Syscall(SYS_IOCTL, …)`, with a local 288-byte `in6Ifreq` struct: `name [16]byte`, then a 272-byte union at offset 16.
    - `SIOCGIFAFLAG_IN6 = 0xc1206949`: flags as `uint32` at union offset 0.
    - `SIOCGIFALIFETIME_IN6 = 0xc1206951`: union holds `ia6t_expire int64`, `ia6t_preferred int64`, `vltime uint32`, `pltime uint32`. Use `DarwinRemaining`.
  - The request carries a `sockaddr_in6` (len 28, family 30, addr; set `sin6_scope_id` for link-local).
  - These ioctl numbers and offsets were verified with the macOS 26 SDK (`sizeof(struct in6_ifreq) == 288`).
  - Watch: `unix.Socket(unix.AF_ROUTE, unix.SOCK_RAW, unix.AF_UNSPEC)`. Signal on any message whose `rtm_type` (byte 3) is `RTM_NEWADDR` (0xc) or `RTM_DELADDR` (0xd). Use `SO_RCVTIMEO` 1 s.
- **Windows.**

### Task 6: Scheduler (retransmit, refresh, heartbeat, lifetime changes)

**Files:**
- Create: `internal/agent/sched/sched.go`, `internal/agent/sched/sched_test.go`

**Interfaces:**
- Consumes: `addrsrc.Addr`, `dhcp6.Infinity`, `dhcp6.RandomXID`
- Produces:

```go
type Key struct{ Addr netip.Addr; IfIndex int }
type Params struct {
	Heartbeat     time.Duration // 1h
	StaticRefresh time.Duration // 4h
	InitialRT     time.Duration // 1s
	MaxTries      int           // 3
	MinRefresh    time.Duration // 10s
	Rand          func() float64 // [0,1); default math/rand/v2.Float64
	NewXID        func() [3]byte
}
func DefaultParams() Params
type Send struct {
	Key       Key
	Addr      addrsrc.Addr // Preferred/Valid recomputed for "now"
	XID       [3]byte
	Try       int          // 1..MaxTries
	Dests     []string     // still-unacknowledged destination names
}
type Scheduler struct{ /* unexported */ }
func New(p Params) *Scheduler
// Update reconciles with a fresh listing. New keys are due now. Keys absent from addrs are
// removed and returned. A >1% lifetime change makes a key due now with a new XID.
func (s *Scheduler) Update(now time.Time, addrs []addrsrc.Addr) (removed []Key)
// Due returns sends whose time has come. A key starting a new cycle takes its destination
// set from dests(addr). Calling Due advances retransmit timers (the caller sends exactly these).
func (s *Scheduler) Due(now time.Time, dests func(addrsrc.Addr) []string) []Send
func (s *Scheduler) Ack(key Key, xid [3]byte, dest string) // ignored if xid is not the current XID
func (s *Scheduler) Forget(key Key)
func (s *Scheduler) Next() (time.Time, bool)              // earliest pending deadline
func (s *Scheduler) Len() int
// RefreshInterval is exported for tests.
func (p Params) RefreshInterval(a addrsrc.Addr, now time.Time) time.Duration
```

Rules:
- Remaining lifetimes are computed as `max(0, stored − elapsed since ObservedAt)`. Infinity stays Infinity.
- After a cycle's try `n` is sent with `n < MaxTries`, the retransmit is due at `InitialRT × 2^(n−1)`, so tries go out at t = 0 s, 1 s and 3 s.
- A cycle ends either when every destination is acked or when try `MaxTries` has been sent and `InitialRT × 2^(MaxTries−1)` has elapsed. Either way the next cycle is due at `start + RefreshInterval`, with a new XID.
- `RefreshInterval`:
  - for `OriginStatic` or `Valid == Infinity`: `min(StaticRefresh, Heartbeat)`
  - otherwise: `min(0.8 × Valid × (0.9 + 0.2 × Rand()), Heartbeat)` seconds
  - in both cases floored at `MinRefresh`
- Lifetime change: compare old expiry (old ObservedAt + old Valid) with new expiry (new ObservedAt + new Valid). If `|Δ| > 0.01 × newValid` seconds, the key is due now with a new XID. Apply the same test to Preferred. Infinite↔finite always counts.
- An `Update` with unchanged lifetimes does **not** reset the timers or the XID.

type Agent struct {
	Src        addrsrc.Source

	DUID       []byte
	Info       sender.Info

	Multicast  string                                        // "auto" | "always"

Loop behaviour:
- One goroutine owns `Sched`. Its select covers: a timer for `Sched.Next()`, the watch channel, the rescan ticker, `Tx.Replies()` and ctx.
- Rescan: `Src.List()` → `Select` → `Sched.Update`. Removed keys → `Tx.Drop`. A List error is logged at Warn and the previous state is kept.
- A watch signal sets a 1 s debounce timer, so a burst of signals yields one rescan. While the timer is pending, further signals do nothing.
- If `Watch` returns an error, log Info and set the rescan interval to `Poll`.
- Destinations for an address: `"multicast"` iff `Multicast == "always"` or the interface's probe result is true, plus `UnicastDest(c)` for each collector. An address with no destinations is skipped, with one Debug log per interface.
- Probe results are cached per interface name and refreshed at heartbeat. Probes run in their own goroutine and report back over a channel, so they never block the loop.
- For each `Send` from `Due`: build once per Send, then `Tx.Send` to each named destination. On `ErrAddrGone`: `Sched.Forget` + `Tx.Drop` + log Info `address gone`, and skip the remaining destinations. Other errors log at Warn, rate-limited to one per address per cycle.
- Reply: find the key by `Local` address. `From` equal to a collector's address → `Ack(key, xid, "unicast:"+collector)`. Also always `Ack(key, xid, "multicast")`.

    - **DUID on Linux.** Only dhclient's `default-duid` is read. On systemd-networkd and NetworkManager hosts the agent's DUID won't match the OS DHCPv6 client's DUID unless `duid` is set in the config. Otherwise a generated DUID-LLT is saved in `agent-state.json` and stays stable across restarts and MAC randomization.
    - **macOS lifetimes** come from `SIOCGIFALIFETIME_IN6` (wall-clock expiry). If that ioctl fails, the address is registered as infinite and refreshed every heartbeat.
    - **Windows** can't distinguish temporary from stable-privacy addresses, so both are reported as `slaac`. Both are registered.
    - **No de-registration.** The end of use is inferred from `last_seen` plus expiry.
    - **Port 546.** If 546 is held by the OS DHCPv6 client, the agent falls back to an ephemeral port.
